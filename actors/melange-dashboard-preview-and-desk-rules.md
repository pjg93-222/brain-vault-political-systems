## Preview and verification workflow (reference, 2026-08-18)

The dashboard UI lives entirely in `fec/templates/make_dashboard_html_00.tpl` (a self-contained HTML+JS page). `fec/build_dashboard_bundle.py` produces `dashboard_data.json` (the audited artifact: the audit only checks that JSON, NOT the tpl/HTML), and `fec/make_dashboard_html.py` injects it via `__DATA__` and writes `Moneyball Dashboard.html` **to the live root** (MB_ROOT, outside any worktree; paths.py doesn't isolate data). `lock_dashboard.py` encrypts `Moneyball.html` -> `deploy/index.html` (a publish step; needs permission).

- **To preview a tpl edit safely (no live-tree writes):** write a tiny builder in scratchpad that does `tpl.replace('__DATA__', json.dumps(json.load(open(<MB_ROOT>/dashboard_data.json))))` -> scratchpad HTML, serve it with `python -m http.server 8899 --bind 127.0.0.1` (run_in_background) and open `http://127.0.0.1:8899/dashboard.html` in the claude-in-chrome browser.
- **Gotcha:** the claude-in-chrome `navigate` tool force-prepends `https://`, so `file://` URLs become `https://file///…` and fail: you MUST serve over http. Node isn't on PATH (bash or PS), so `node --check` won't run; the real syntax/behavior check is loading in the browser + `read_console_messages(onlyErrors)` + driving the UI via `javascript_tool` (call page fns directly: `selectMember`, `runPath`, `cascadeRun`).
- **rAF is throttled when the tab isn't focused**, so time-based animations won't advance frame-by-frame in headless drives: force the end state with `routeAnim.t0=performance.now()-2000; draw()` before screenshotting.
- **READ THE PREVIOUS SENTENCE BEFORE DEBUGGING AN ANIMATION. 2026-08-18: I did not, and burned five rounds "diagnosing" correct code.** In the Claude_Browser pane `document.visibilityState` is `'hidden'` and **rAF fires ZERO frames**, and it STAYS hidden after `tabs_select` / fronting, so you cannot fix it by fronting the tab. `computer{action:'screenshot'}` also refuses ("the Browser pane is not displayed, so the page is not compositing frames"). An rAF-driven tween therefore executes its synchronous frame 0 (which by construction sets position = start) and then freezes, so **working code presents exactly as "the feature does nothing"**, and every assertion downstream fails, which reads as a broken implementation rather than a broken harness.
