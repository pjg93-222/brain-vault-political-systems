## DE-032 - Reading a shrinking `git status` or an empty ripgrep as proof that files were deleted
Date: 2026-09-18
Approach: A fix agent saw `git status` fall from 273 entries to 103 and its ripgrep stop finding hits in `*.bak-*` files, and reported that a sibling agent had deleted the backups.
Failure mode: Nothing had been deleted. An ignore rule for `*.bak-*` had landed minutes earlier; all 167 files were on disk.
Root cause: `git status` and ripgrep both honour .gitignore, so an ignore rule and a deletion look identical through either.
Would reconsider if: Never. Existence is a filesystem question: `Test-Path` / `Get-ChildItem`, or `git ls-files --others --ignored --exclude-standard`.
