## DE-033 - committee | report type | transaction id as the identity of a transaction
Date: 2026-09-19
Approach: Group FEC bulk rows (itoth, itpas2) by committee, report type and transaction id, call each multi-row group "competing versions of one transaction", and resolve or withhold the group as a unit.
Failure mode: Filers reuse a schedule line label as the transaction id - `SE.5` on every Schedule E row of every filing, `SB22.n` every year - so genuinely different transactions (different candidates, vendors, dates, amounts) collide. Withholding the group dropped $7.63M of real committee-to-candidate activity and, with a committee-level blacklist on top, blocked $152.5M of clean transfer edges; resolving the group would have kept one row and silently dropped the others. 827 of 2022's 1,130 groups sat inside a single filing, where no filing header can ever help.
Root cause: A transaction id is unique only inside the filer's own software's idea of a filing, and many filers do not even honour that. Identity is the counterparty, amount, date and type.
Would reconsider if: Never as an identity. It remains a useful GROUPING key - [[ledger/melange-systems-brain/D-049|D-049]] partitions inside it.
