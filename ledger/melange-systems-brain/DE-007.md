## DE-007 - Wrapping the member-desk payload in JSON.parse for load latency
Date: 2026-08-24
Approach: Replacing the desk's 42.2M-char inline `const D={...}` object literal with
`const D=JSON.parse('<escaped>')` on the folk rule that JSON.parse beats literal eval for large
payloads. Escape proven byte-identical round-trip before measuring, so the comparison was clean.
Failure mode: Measured 6.5x SLOWER on the paired in-page metric - literal eval 46ms vs JSON.parse
300ms (plus ~37KB escaping growth). domContentLoaded worsened in the same direction.
Root cause: V8 (and this box's Chrome) has a fast path for plain object literals that outruns
string re-parse at this scale, and the 42MB single-quoted string adds tokenizer cost the literal
never pays. The folk benchmark dates from engines where the literal path was the slow one, and
from payloads parsed inside cold functions - neither holds here. Payload eval was never the
bottleneck anyway: it is 46ms of a ~1.8s load; transfer+HTML-tokenize of the 40.6MB file is the
real cost (attacked instead by the split-desk prototype, same session).
Would reconsider if: The payload stops being a plain-literal-friendly shape (e.g. becomes deeply
string-heavy), or an engine change makes literal eval regress - re-measure with the same paired
in-page instrumentation before believing either direction.
