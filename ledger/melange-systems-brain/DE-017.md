## DE-017 - Deriving a repo's "correct pattern" by recursing from the live root into `.claude/worktrees/`
Date: 2026-09-06
Approach: A read-only verification agent was asked to infer the house idiom for an import-guard pattern from how non-offending files in the same directory already do it, and searched for those examples starting from the live tree root rather than from a git-tracked view. Because `.claude/worktrees/` lives directly under that root, the search descended into it and read another lane's uncommitted, in-flight edits: at 2026-09-06 15:17:10 it ran a `head -30` on `staffer-network-stale-imports-2e9e82/fec/surfaces/staffer_identity_auto.py`, a file mid-edit in an unrelated worktree, and reported the pattern it found there as established house style.
Failure mode: The parent session then applied that inferred idiom to the LIVE tree at 15:54:07 across 15 files belonging to the other lane, with the fix script's own docstring asserting it was following "the established sys.path bootstrap" - a string that exists in zero committed files, zero pre-edit backups of those files, and zero hits in `git grep HEAD`. One lane's uncommitted, still-in-progress pattern was silently promoted to "house convention" and then written into a different lane's out-of-scope files in the live tree.
Root cause: The live tree root is not a clean corpus for pattern derivation, because `.claude/worktrees/` nests every other lane's uncommitted, in-flight work directly beneath it. A sweep that recurses from that root cannot distinguish an established repository convention from another lane's mid-edit draft, so "derive the convention by reading around" turns silently into cross-lane inheritance, compounded here into an out-of-lane write to the live tree.
Would reconsider if: never for recursing from the live root. Pin pattern-derivation sweeps to `git grep HEAD` (or run them with an explicit exclusion such as `--exclude-dir=.claude`), so that only committed code can ever define a convention; a worktree's uncommitted content must never be eligible evidence for "how this repo does things."
