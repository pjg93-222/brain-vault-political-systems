## D-012 — Ultracode overrides the standing no-workflow line (ORCHESTRATION ONLY)
Date: 2026-08-18
Status: ACTIVE
Decision: When the ultracode setting is ON, it overrides the Melange session-guidance line "do not use workflows or the AgentTool unless the user requested it". Fan out with Workflow by default on substantive work; do not ask permission to orchestrate. The override is scoped to ORCHESTRATION and confers NO apply authority.
Context: The session guidance forbids unrequested fan-out while the ultracode setting instructs the opposite. The coordinator surfaced the conflict instead of silently resolving it; Paul ruled for ultracode verbatim: "Yes, keep ultracode overriding that going forward".
Rationale: The no-workflow line exists to prevent token burn on fan-out Paul did not ask for. Enabling ultracode IS that request, stated once as a setting rather than retyped each turn; requiring a per-task ask would defeat the setting. Scoping it to orchestration keeps the two bordering laws intact: (1) the ask-first APPLY gate (2026-07-15) still governs every edit, regeneration and commit -- fanning out read-only reviewers and then landing their fixes unasked breaks that gate exactly as badly as doing it solo, so the required shape is fan out on investigation, synthesize, present, WAIT; and (2) the SUBAGENT LAW (2026-08-07, commands/metaloop.md) still binds -- subagents are READ-ONLY Fable reasoning lanes that never edit files, never run producers and never dispatch Codex themselves, and every subagent prompt must state that contract. Ultracode raises the volume of reasoning lanes; it grants them no write authority. Judgment is retained for conversational, governance and trivial-mechanical turns, where a fleet is theater rather than thoroughness.
Reversal condition: Paul turns ultracode off or states the override no longer applies; or fan-out is observed producing apply-gate violations, in which case the orchestration default is withdrawn rather than the gate weakened.
