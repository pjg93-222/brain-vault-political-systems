## DE-025 - Cutting a patch through a text-mode subprocess on a cp1252 console
Date: 2026-09-17
Approach: The S5 patch cutter captured `git diff` through `subprocess.run(..., text=True)` and wrote the result back as UTF-8. On this box the locale codec is cp1252.
Failure mode: Every non-ASCII character in a changed line (em dash, middle dot, ellipsis) came back as mojibake and re-encoded to different bytes; `git apply --cached --check` refused exactly the three files whose hunks carried non-ASCII (HANDOFF.md, chart-studio.js, graph.js) while each applied cleanly on its own. Had the patch been trusted, Paul's commit would have silently corrupted those characters.
Root cause: text-mode decoding uses the locale, not the repository's UTF-8; a diff must be carried as bytes end to end.
Would reconsider if: never. Cut and write patches as bytes (`subprocess.run(..., capture_output=True)` without `text=True`, write with `wb`), and prove them with `git apply --cached --check` before handing them over; a per-file apply that succeeds while the whole patch fails is the signature.
