## D-267 — brainlink hook stop: only a tool failure counts as a stage failure
Date: 2026-10-20
Status: ACTIVE
Decision: A brainlink hook stop counts a stage as failed only when its exit code is > 1 or its status is partial/failed. Check exit 1 (drift found, the tool ran) is not a failure and still allows the "ok" stop record. Run-lock contention emits Glass Box "blocked", writes a not-ok hook record, and is not "failed".
Context: Decided by Claude (coordinator) 2026-10-20 under Paul's 2026-10-19 execute-without-asking delegation (implementation choice, NOT a Paul ruling; Paul may overrule). Landed in Project Brain 618dce9 (hook stop records failure when a stage fails instead of "ok") and 0892bff (lock contention reported as blocked); the Project Brain repo has only the local mirror remote. Part of the 2026-10-20 small tooling lane.
Rationale: The check stage's own record already carries error counts; counting drift as failure would disable the throttle while drift persists, and lock contention is common with parallel sessions.
Reversal condition: Paul wants drift to mark the Stop hook failed.
