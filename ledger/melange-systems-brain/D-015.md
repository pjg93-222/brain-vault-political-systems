## D-015 — Raise the sentinel hash cap for git stores
Date: 2026-08-27
Status: ACTIVE — implementation pending at time of writing
Decision: Raise `SENTINEL_HASH_MAX_BYTES` (or make it unbounded) for git stores so content-addressed pack files are actually hashed rather than skipped.
Context: The 2026-08-27 git-bookkeeping fix ([[ledger/melange-systems-brain/DE-011|DE-011]]) correctly removed the volatile sentinels. For `repo.git` the removed row (`index`) happened to be its ONLY hashed sentinel, and all three surviving content-addressed rows exceed the 8 MiB cap (3.25 GB pack, 398 MB pack, 209 MB lost-found blob), so each records `sha256: null`. Measured across the two committed manifests: `repo.git` 4 sentinels/1 hashed -> 3/0; `mirror.melange` 4/2 -> 3/1; `mirror.glassbox` 4/4 -> 3/3.
Rationale: `repo.git` was left DECLARING `sentinel_files` while carrying no content-verifiable evidence at all -- A2b could compare only size and mtime. `mirror.melange` and `mirror.glassbox` are the two `irreplaceability>=3`, single-disk, no-off-box-replica stores named in the extinction census, so they are exactly where byte-level evidence matters most. Both halves of the honest framing are true: EVIDENCE QUALITY WENT UP (the removed hashes were guaranteed false positives -- `index` changes on every commit) while EVIDENCE COVERAGE WENT TO ZERO for repo.git. This closes the coverage half without reopening the quality half.
Cost accepted: roughly 3.64 GB (repo.git packs) plus 3.15 GB (mirror.melange pack) hashed per run; `audit_full` already takes ~17 minutes. Paul was shown the cost and accepted it. The implementing lane MUST MEASURE the actual added seconds and record the number rather than assume it.
Scope: this is the SENTINEL hash cap, a different dial from `hash_always`. It does NOT widen [[ledger/melange-systems-brain/D-014|D-014]].
Open interaction, not yet ruled: `lost-found/other/c7c1b92c...` (209,700,168 B) is currently repo.git's third sentinel and is `git fsck` scratch from 2026-07-27. Raising the cap means hashing 209 MB of recovery garbage every run. The lost-found exclusion is a separate defect whose cost this decision raises.
Reversal condition: measured hashing cost makes the gate impractical at its required cadence -- then fall back to requiring one UNDER-cap hashable sentinel per store, which was the rejected alternative and remains the cheap substitute.
