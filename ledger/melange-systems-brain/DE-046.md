## DE-046 - Comparing file or ISO timestamps with time.time() without clock slack
Date: 2026-09-20
Approach: verified_completion() rejected receipts whose st_mtime or started_at was below started_epoch, with no tolerance.
Failure mode: test_daily_refresh failed intermittently and made kernel comparisons unreliable. The prior investigation measured 1 failure in 40 normal suite runs and 17 failing runs in 40 amplified runs.
Root cause: Under Python 3.12, time.time() and st_mtime round the same coarse clock tick to floats differently, and datetime.now() floors to microseconds. Under Python 3.13+, the precise process clock can lead the coarse file stamp by a tick (19.33 ms maximum in the saved clock probe). Relaxing only the three file-time checks leaves the ISO comparison broken.
Would reconsider if: Never for strict ordering across these clock representations. Use a measured tolerance, as the wrapper and daily gate now do, or compare integers from one clock. Pin every comparison with independent stale-reading controls.
