## D-060 — Patches against LIVE bytes are cut line-wise with fec/tools/live_patch.py; LIVE files are never EOL-normalised
Date: 2026-09-19
Status: ACTIVE
Decision: Any patch cut against the LIVE working tree's bytes is cut with fec/tools/live_patch.py (landed 423820d76): bytes end to end, lines split on LF only, anchors matched per line with the terminator stripped and required to hit exactly once, new lines carrying the file's majority terminator, untouched lines never rewritten; proved with prove() and applied with `git -c core.autocrlf=false apply` to the working tree (apply_to() refuses a target that moved since the cut and a manifest that does not name the patch's files). The working files themselves are left alone: no `.gitattributes` eol rule and no normalisation pass.
Context: Paul 2026-09-19, answering the presented census, recommendation and five rulings: 'Reconcile those loose ends and apply'. A spawned task had reported ONE bare-LF line in LIVE fec/audit/dashboard_integrity.py; the census found 88 in that file and, at main 35521f9aa, 312 of 2,892 tracked text files MIXED in the working tree (279 code), 1,622 pure LF and only 949 pure CRLF, every one of their blobs pure LF (the only blobs carrying CR are four .patch files stored -text on purpose); 78 more MIXED among 28,464 untracked text files. The inserted-line rule was put to him as anchor-inherit (what n1_cut_live_hook.py did, which grew build_media_blend.py from 47 to 54 bare-LF lines at the 09-19 landing) against majority-inherit with a stated lean to majority; majority is the default and eol='anchor' stays available.
Rationale: No single terminator assumption holds anywhere in LIVE, so a string-replacement anchor spanning CRLF returns -1 on a mixed file while an EOL-normalised hash reports no drift. Measured on git 2.54.0.windows.1 (scratchpad eol_lab): a working-tree normalisation changes no blob, blame or file:line pin but would make 1,934 content-identical files read ` M`, because git status flags a size change against the index without comparing content, sticky until `git add`; it would invalidate every outstanding live-bytes patch; and it decays, since tools keep writing LF. A committed `* text=auto eol=crlf` rewrites no working file and overrides [[ledger/melange-systems-brain/D-048|D-048]]'s clean-export flags. Mixed files are repaired anyway whenever a merge rewrites them (four were on 2026-09-19).
Reversal condition: A census (`python fec/tools/live_patch.py eol`, or the scratchpad eol_census.py) shows LIVE uniformly one terminator and staying so across a month of lane activity; or git gains a working-tree renormalise that does not mark size-changed, content-identical files modified.
