## D-183 — Automatic propagation: any change updates everywhere
Date: 2026-10-12
Status: ACTIVE — decided by Paul 2026-10-12 (his answer "We have to make this all updateable, so if any change ever gets made, it updates everywhere else."). Amends [[ledger/melange-systems-brain/D-168|D-168]], manual-v1 clause only.
Decision: Any committed change (Melange main, Mentat codex/mentat-crypto, the Terrier release branch) triggers, after a quiet period, an automatic release. Only images whose inputs changed are rebuilt; the others reuse their digest. All image digests (apps and compute) are signed on the laptop into one platform manifest, which the VPS updater (apps) and the laptop's compute wrappers (via the verified current manifest) both follow. GitHub releases are published. Idle Mentat consoles are restarted through the launcher's existing idle-stale mechanism ([[ledger/melange-systems-brain/D-029|D-029]]). Netlify updates only when the invited build changed and governance is ruled ([[ledger/melange-systems-brain/D-171|D-171]]). Finished refreshes trigger data releases through the existing gates. Gates still fail closed ([[ledger/melange-systems-brain/D-169|D-169]], [[ledger/melange-systems-brain/D-181|D-181]], [[ledger/melange-systems-brain/D-182|D-182]]); a failure stops propagation and alerts. Scheduling is a Task Scheduler task that Paul approves when it is registered.
Context: [[ledger/melange-systems-brain/D-168|D-168]] made ops/release.py the single release action but said v1 releases are run by hand, and deferred an automatic data release after the weekly refresh until Paul asks for it. This ruling replaces that manual-v1 clause with automatic propagation; the data-release trigger on finished refreshes is the step [[ledger/melange-systems-brain/D-168|D-168]] deferred. Unchanged: ops/release.py as the release action, the laptop-signed manifest that the VPS verifies, the four package types, and the fail-closed gates of [[ledger/melange-systems-brain/D-169|D-169]] as amended by [[ledger/melange-systems-brain/D-181|D-181]] and [[ledger/melange-systems-brain/D-182|D-182]]. The compute wrappers follow the verified current manifest because [[ledger/melange-systems-brain/D-173|D-173]] and [[ledger/melange-systems-brain/D-175|D-175]] put the compute containers on the laptop; the idle-stale restart is [[ledger/melange-systems-brain/D-029|D-029]] (Start-MentatApp.ps1 restarts a stale console on the same port only when it is idle); the Netlify step is [[ledger/melange-systems-brain/D-171|D-171]]'s desk. This entry records the ruling only: the quiet period, the auto --pause switch and the Task Scheduler task are for the build to deliver, and nothing is registered or built by this entry. Source: Paul's answer in this session, relayed in the orchestrator's brief for this brain update; the mechanism wording and the reversal condition below come from that brief, not from Paul's words.
Rationale: Paul's call. His reason as given: everything must be updateable, so that a change made once reaches every other place that runs the platform. The gates stay fail-closed and a failure stops propagation, so automation does not bypass the checks that a manual release passed through.
Reversal condition: Paul pauses auto-release (release.py auto --pause) or reverts to manual releases.
