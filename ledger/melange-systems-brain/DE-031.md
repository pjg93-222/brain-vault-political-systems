## DE-031 - A green suite in a dirty working tree as proof that HEAD works
Date: 2026-09-18
Approach: After committing part of a shared dirty checkout (whole-file or hunk-exact), run the suites in that same checkout and read green as "the commit is good".
Failure mode: In C:\Users\pgoff\Mentat, HEAD was broken in twelve places for up to five days while every lane's receipts showed green: committed comparison_data.py read a key only the uncommitted graph_data.py produced (HTTP 500 on any clean checkout), nine client modules read an `accounting` payload only the uncommitted report_insights.py produced and guarded every read with `|| {}` (so the refusals silently never fired), four launchers imported an untracked module, the workbook builder imported an untracked .mjs, the exporter sourced an untracked R file, and three committed tests were red against committed code.
Root cause: The working tree supplies every missing file to every test. `97eaa7581` tracked 35 modules and none of their tests; later whole-file commits took sources and left siblings behind. Extension-wide ignore rules (`*.json`, `*.txt`, `mentat/inputs/`) hid the rest from `git status`.
Would reconsider if: Never as the only proof. Pair it with the clean export in [[ledger/melange-systems-brain/D-048|D-048]]'s Dials line. A plain `git archive` is itself a trap here: with core.autocrlf=true it emitted CRLF for LF blobs, so the first export was not the commit.
