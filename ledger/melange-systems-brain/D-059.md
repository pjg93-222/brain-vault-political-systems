## D-059 — The Melange mirror pushes itself on every commit and merge
Date: 2026-09-19
Status: ACTIVE
Decision: The Melange repository pushes itself to its mirror: .git/hooks/post-commit and post-merge push the branch just committed or merged to remote mirror (C:\Users\pgoff\GitMirrors\melange-systems.git) - one branch, never forced, never able to fail or block the commit.
Context: Paul 2026-09-19: 'add the hook to melange too', after the brain mirror ([[ledger/melange-systems-brain/D-058|D-058]]). The hooks directory is shared by all 16 linked worktrees, C:\Users\pgoff\Mentat (codex/mentat-crypto) included, so commits there mirror themselves too. Tested: sh -n; success path from the live tree and a session worktree; failure path on a scratch copy (exit 0, log line, valid event); one real empty commit b99ba565d on the session branch moved the mirror by itself. Tags are not pushed by the hook.
Rationale: The mirror had been found eleven days stale on 2026-09-19 (main at 2049fea9f, 88 of 292 branches absent) because pushing was a manual step every lane forgot. A single-branch push to the local bare mirror measures 0.2 to 1.2 seconds, so it runs synchronously. post-merge is installed as well because a fast-forward merge makes no commit. A failed push (mirror missing, non-fast-forward, lock) exits 0, appends a line to .git/mirror-push-failures.log and emits one FAIL event to the Glass Box stream (source melange-mirror-hook); a push is never forced, so the mirror keeps the older history when a branch was rewritten.
Reversal condition: The hook is seen delaying or breaking commits (then push in the background with all three standard streams redirected, or from the lane close-out instead), or the GitMirrors folder leaves Carbonite's backup set. .git/hooks is not versioned: re-create both files after any re-clone.
