## DE-040 — Committing .patch files as text, and applying a patch in-rep
Date: 2026-09-19
Approach: Committing .patch files as text, and applying a patch in-repo to a producer with mixed line endings
Failure mode: The merge checked the packet's patches out CRLF-converted and the live copies stopped applying. fec/stance/build_media_blend.py had 433 CR over 480 lines, and in-repo git apply under autocrlf stopped matching its LF-only hunks although the same bytes applied cleanly outside a repo.
Root cause: autocrlf normalises text blobs on commit and converts them on checkout; a patch is only valid as exact bytes. Git Bash also mangles branch/with/slash:path arguments (use the SHA, and MSYS_NO_PATHCONV=1 on that command only).
Would reconsider if: Patches stored under a -text attribute and applied on a scratch copy outside the repo, md5-proved against a dry run, then copied back (done 2026-09-19; packet landing/LANDED.md).
