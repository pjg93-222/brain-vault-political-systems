## D-045 — The console's build stamp never waits on a revision lookup
Date: 2026-09-18
Status: ACTIVE
Decision: The git sha in the console's build stamp is display-only, so no request may block on a revision lookup: `/api/session` and `/api/health` return `'unknown'` immediately and a single daemon thread fills the value in. Corollary, which cost this lane a wrong design spec before it was caught: `PROJECT` in `mentat/app/server.py` is `Path(__file__).resolve().parents[1]`, i.e. `<checkout>/mentat` and NOT the checkout root, so `PROJECT/'.git'` does not exist and any reader of git metadata must search upward the way `git rev-parse` does from its cwd.
Context: this lane, 2026-09-18, on the fault the collector-slowdown lane diagnosed on 2026-09-17 (`audits/mentat_collector_slowdown_20260917/DIAGNOSIS.md`, commit `b9fe34d02`); committed `0ad366e01`.
Rationale: the stamp can degrade without affecting any gate. `app.js` already falls back to `code_sha256` when the sha is `'unknown'` (`mentat/app/app.js:436`), and [[ledger/melange-systems-brain/D-029|D-029]]'s restart gate compares `on_disk_code_sha256_now` against `code_sha256` and never reads the git sha (`server.py:2608`; the comment at `server.py:198` records the same in the code). `build_status` keeps all nine fields and the code and asset hashes are computed exactly as before.
Measured: the route answers in 0.016 s with the lookup blocked for 30 s; the direct reader answers `b9fe34d02` in 0.0000 s where `git rev-parse --short HEAD` takes 0.42 s.
Reversal condition: the git sha becomes load-bearing for a gate, or a transient `'unknown'` is observed causing a wrong restart.
