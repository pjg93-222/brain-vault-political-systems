## D-047 - Sparse-checkout before removal; a data directory's relevance is read from the running program
Date: 2026-09-18
Status: ACTIVE
Decision: The first disk lever on a session worktree is a per-worktree sparse-checkout that excludes `audits/legfix5` (`git -C <tree> sparse-checkout set --no-cone '/*' '!/audits/legfix5/'`), not removal. It applies to Mentat-lane trees and to tabled trees; it never applies to a Melange-lane tree without Paul's word, because the legislation producers and audits read that directory. Beyond worktrees, a file is a clearing candidate only when the running program is shown not to use it: the selecting code is cited by file and line, config pointers are checked as well as code, a duplicate is verified file by file against the copy that stays, and anything cited as evidence keeps its report and its hash. Inside a backup-like directory only large generated surfaces go; receipts, workbooks, logs and data stay. Tabled lanes (staffer and member-relationship networks, audio, lobbying and contact inference) and every session scratchpad stay off limits.
Context: The fifth clearance in eight days. Paul ordered 200 GB cleared with the tabled lanes saved, declined the first three deletions offered (one of them a byte-duplicate inside a scratchpad), asked instead for a comparison against "the main state of the program" for both Mentat and Melange, approved its three groups, and then ordered the rest of the list cleared.
Rationale: The sparse lever returned 119.2 GB from seven trees at under twenty seconds each with nothing removed. The relevance method returned 86.0 GB, and its config-pointer check stopped the deletion of the console's active FEC source, which no code references by name. A tree's lane is read from its transcript's first prompt, not from the worktree's name.
Reversal condition: `audits/legfix5` stops being tracked (then a checkout costs under 1 GB and the lever is moot), or Paul names a Melange-lane tree or a scratchpad for it.
