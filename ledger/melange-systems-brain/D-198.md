## D-198 — Terrier FTS5 shadow tables: compared by rebuilt form and MATCH answers, not by layout
Date: 2026-10-13
Status: ACTIVE — decided by Claude 2026-10-13 under [[ledger/melange-systems-brain/D-177|D-177]] (an implementation decision for SQLite stores, not a Paul ruling); Paul may overrule it.
Decision: When the shadow tables of an FTS5 table (_data, _idx, _docsize, _config, _content) are not exactly equal between the Windows build (A1) and the container build (B), they are compared by content instead: (i) equal after an FTS5 'rebuild' by one SQLite library on scratch copies of each side, and (ii) 400 MATCH queries (a seeded sample of A1's indexed words) return the same rowids on the stores as built. Every other table, and a table that only looks like a shadow, stays exact. A contentless FTS5 table (content='') cannot be rebuilt, so its shadow tables must be exactly equal or the comparison fails. Terrier commit db17ac4, with the contentless refinement in cba5e34.
Context: [[ledger/melange-systems-brain/D-177|D-177]] compares SQLite stores by content, every table row identical. The shadow tables of an FTS5 index are its physical layout, which the SQLite library decides, so they can differ between SQLite versions while the logical index is the same. Read 2026-10-13 (read-only, git and COMPUTE.md in the Terrier live checkout, branch claude/walk-list, tip bd319d5 at the read): the Terrier full-chain parity run of 2026-10-13 (c6116c4, 02:33) had roads, street, contacts and shown pass and scores exact in every table except the two FTS5 shadow tables of the demo-name search index (SQLite 3.40.1 against 3.49.1; 400 of 400 MATCH queries identical and equal after a rebuild by one library); the harness kept reporting FAIL and that commit did not change the rule. db17ac4 (11:07) made the rule change, with a negative control (change_one_indexed_name: one indexed value changed with the index kept in line must fail the FTS comparison itself, run for every store that has an FTS5 table) and --reuse-container to judge a finished run again without building; cba5e34 (12:36) added that a contentless table (contacts.sqlite3's search) is compared exactly or fails, found by the re-judge. The re-judge of the finished run: PARITY PASS 17 of 17 with every negative control detected (Terrier COMPUTE.md section 9, bd319d5). Rationale: Claude's call under [[ledger/melange-systems-brain/D-177|D-177]]: content equality is the strictest standard that can be met for an FTS5 index, because the library decides the layout.
