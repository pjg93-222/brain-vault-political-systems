## DE-028: Dating code by its commit date in this repository
Approach: Deciding whether the FEC response archive could have witnessed a given collection run by comparing the run's date with the commit date of the archive code (`fec_response_archive`, d78cf0b8f, 2026-09-16).
Failure mode: the inference was made twice and was wrong both times, in opposite directions. First it concluded the archive could not have covered Banking's 2026-09-09/10 collection because the code was committed six days later. Then, corrected by a peer lane, it concluded the archive might well have covered it, since the code had been running uncommitted in the working tree beforehand. Neither conclusion was supported, and a live FEC re-fetch was nearly authorised on the strength of the second.
Root cause: the Mentat runtime is re-staged from the working tree at every launch, so a commit date bounds neither the earliest nor the latest execution of the code it records. Code in this repository routinely runs before it is committed, and a committed file may never have run at all.
Would reconsider if: never for commit dates. Date code from its own output. The question was settled by reading the earliest and latest rows the archive actually wrote (2026-09-15T15:23:13 to 2026-09-17T15:55:37) and, independently, by the `scraped_at` and `load_date` values on the collected rows themselves.
