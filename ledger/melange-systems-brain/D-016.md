## D-016 — A named stage per dispatched node, and stage-complete only on an adjudicated result
Date: 2026-08-27
Status: ACTIVE — committed to `.claude/commands/metaloop.md` §3 at `a5166d166`
Decision: Every node the coordinator dispatches — subagent, Codex round, workflow, perception or critique lane — gets its OWN `stage-start`, named with the node ID from the plan, carrying that node's falsifiable check, impact envelope and reversal verbatim in `-Detail`. `stage-complete` is emitted ONLY after the node's result is in hand and adjudicated: never on dispatch, never on a timer, and never inferred from a derived `agent.completed`. In full mode each dispatched node also gets its own reconciliation rather than being folded into a batch.
Context: Paul, verbatim: "Make sure to run the metaloop in the sub tasks", then "This needs to be permanently committed to the metaloop code". The GLASSEYE-derived fan-out pair already existed, but it is anonymous (`general-purpose: <description>`), carries no check, and cannot say what a node was for or how anyone would know it failed.
Rationale: The plan names the nodes; the stream must name them too, or a run is legible only to whoever wrote the plan. The second half is not stylistic — it exists because the derivation's close condition was measured wrong ([[ledger/melange-systems-brain/DE-013|DE-013]]), so a derived completion is evidence that a dispatch HAPPENED, never that a node FINISHED. A batched reconciliation cannot record which node invalidated which assumption, which is the only thing a reconciliation is for.
Reversal condition: the per-node stage discipline is shown to add noise without adding legibility — i.e. a reader can reconstruct which node produced which finding from the derived pairs alone. That is currently false by construction.
