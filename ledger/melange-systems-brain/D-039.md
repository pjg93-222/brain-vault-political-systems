## D-039 - The hash names the tab; the query string carries the scope
Amended: 2026-09-19 by [[ledger/melange-systems-brain/D-061|D-061]] - `studioPane` no longer names a pane. It is a retired key that scope.js ignores and preserves (contracts/url_scope.json v4); everything else here stands.
Date: 2026-09-17
Status: ACTIVE
Decision: The Mentat console's URL is its navigational state. The fragment names the tab (existing behaviour) and the query string carries the scope with the Graph API's own key names (`industry`, `company`, `cycle`, `mode`, `direction`, `tier`, `funding`, `category`, `recipient`) plus `saved`; `studioPane` stays; `evidence`, `id`, `committee`, `offset`, `limit` are reserved for the two-pane model. Only `mentat/app/scope.js` reads and writes these keys; writes use history.replaceState, never pushState; defaults are absent from the URL; unknown keys are preserved. No second state store (no new localStorage or sessionStorage keys) may carry navigational scope.
Context: S5 of the mentat-failings lane, design accepted by Paul 2026-09-17 with rulings A(ii)/B/C; committed `a7e09ed8c`; contract contracts/url_scope.json v1.
Rationale: Chart Studio already read `?industry=` and S3's pane model already committed the evidence pane to query keys, so the query string was the established direction; a fragment-only replaceState keeps the query, so tab switching preserved the scope without new code; one vocabulary shared with the API keeps a permalink and a request identical.
Reversal condition: a view whose state cannot be expressed as flat query keys, or Paul choosing pushState so Back walks the tabs (ruling C reversed).
