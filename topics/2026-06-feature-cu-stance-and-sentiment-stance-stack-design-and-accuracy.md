## Two-hop stance stacks: the 2026-07-04 accuracy campaign (source `moneyball-stance-decomposition`)

Concept summary: [[two-hop-stance-decomposition]]. Full record:

**The definitive stance-accuracy diagnosis (2026-07-04, user "we can break 80%", Opus-mode).** Measured on the 400 tweet golds by decomposing `cu_alignment` into its two hops (the API already stores both fields: `gold/api_stance_toward_target` + `gold/api_target_cu_valence`):

- **STANCE hop** (member's stance toward the target): model **0.915**, essentially solved.
- **VALENCE hop** (is the target good/bad for CUs): model **0.689**, THE bottleneck. The model systematically fails PRO-CU targets, calling 57/128 gold +1 targets "neutral" and 23 "negative". It knows CFPB/interchange are anti-CU (0.78 on negatives) but cannot know FOM-expansion / MBL-relief / reg-tailoring are PRO-CU.

## Kim position-classification benchmark (2026-08-03; source `kim-position-classification-2026-08-03`)

Paul, 2026-08-03: "You should be following the same format as In Song Kim when classifying, remember you were far too conservative whereas he was inferential." He was right, and the mechanism was measurable.

### The structural fact that breaks naive metrics

**Kim's `label_5_class` column stacks TWO annotators with different label spaces.** Never evaluate across them:

| lane | rows | Support | Oppose | Amend | Monitor | Engage |
|---|---|---|---|---|---|---|
| gnn | 196,683 (70%) | 27.6% | 2.8% | **0** | **0** | 69.7% |
| llm | 82,421 (30%) | 30.5% | 6.9% | 11.3% | 51.3% | **0** |

gnn is a 3-class model (`label_5_class == label_3_class` on 100% of its rows); llm never emits Engage. **So "Amend F1 = 0.00", which was used to justify collapsing to 3-class, was scoring Amend against an annotator whose label space contains no Amend.** It measured the annotator. Five-class is only evaluable on llm-annotated pairs.

### The prompt defect

`classify_bill_positions.py` substitutes **"Mention" for Kim's "Engage"** (`THEIR_TO_OUR_LABEL = {"Engage": "Mention"}`); "Mention" invites the passive read and absorbed 59.5% of all labels. Also, the cached fewshot exemplars had `Support: 0, Oppose: 0` (only 6 candidates survived its leakage guard): the prompt meant to teach directional labels demonstrated none. Because Kim's llm lane emits zero Engage, **his LLM prompt offered a FOUR-way forced choice** (Support / Oppose / Amend / Monitor, no non-committal escape). That is `kim_llm4` in `fec/lobby_position_prompt_ab.py`.

### The benchmark (the one that counts)

`fec/lobby_position_benchmark.py`: **876 (org, bill) pairs** where Kim's dataset overlaps our work items; 4,697 activity items; natural base rates, no stratification; five-class scored on the 335 llm pairs only. Five-class accuracy: **shipped 0.409 -> kim_llm4 0.821** (kim_zeroshot 0.835 on majority rule). Support count on llm pairs: **Kim 42, kim_llm4 42 (exact)**, shipped 17, kim_zeroshot 25. Amend: **nobody recovers it**: kim_llm4 finds 0 of Kim's 23; only `kim_llm4_fewshot` finds any (recall 0.217) and it costs Support (42 -> 32). **THE ACCURACY TRAP: do not select on 3-class accuracy.** Predicting Engage for all 876 pairs scores **0.8950**; the shipped prompt's 0.8961 is **+0.001 over guessing**; kim_llm4 scores 0.8071 (below baseline) while finding 59% of Kim's Supports vs shipped 35%.

### Prompt caching: measured, NOT worth it here (Paul asked 2026-08-03)

- **Haiku 4.5's cache minimum is 4,096 TOKENS**, bisected against the live API (4,014 does not cache, 4,209 does), NOT the widely-quoted 2,048. Assuming 2,048 would mark ~2,200 items for a cache that never materialises, each paying 1.25x on a write that is never read.
- Redundancy is real: 22,660 work items from **3,698 distinct paragraphs** (6.13 items each), but only **17 paragraphs** are both >= 4,096 tokens and reused: 178 items, 0.8%. Net saving ~5% (~$0.62 on a ~$13 run).
- **The reorder needed to cache is NOT behaviour-neutral.** Kim's layout puts `bill_no` in the opening sentence, so items sharing a paragraph diverge in ~15 tokens and cache nothing. Moving the text first (same sentences) changed **25% of labels** on a 500-item parity check (69 of 377 flipped Monitor -> Support); text-first biases the model toward Support. Shipping it would need a fresh benchmark against Kim, costing more than it saves.
- `kim_llm4_cached` exists in `lobby_position_prompt_ab.py`, fan-out aware (never writes a cache for a single-use block); use only on a corpus with much longer filings, and re-benchmark first.
