# Stage 5 overhaul: DEBATE stance + LSD tone (Congress R scrapers)

> The Stage 5 overhaul of 2026-06-21 to 06-24 that replaced regex scoring with Political DEBATE stance and Lexicoder LSD tone: design, environment constraints, validation, the fine-tuned base model, the deliverable change and the full-corpus deploy. ## Stage 5 overhaul: Political DEBATE (stance) + Lexicoder LSD (tone) (2026-06-21 to 2026-06-24)

Cross-reference: CU stance and sentiment scoring and [[debate-stance-model]] carry the model-centric view; this section keeps every fact recorded in the source files for this topic.

### Design (user decision, 2026-06-21)
Overhauling Stage 5 of the CU press scraper (see the fallback-chain notes in [[2026-06-feature-congress-r-scrapers-cu-press-scraper]], `project_congress_press_fallbacks`) into two SEPARATED layers: **Stage 5a STANCE = Political DEBATE** (direction: support/oppose/neutral toward credit unions), **Stage 5b TONE = Lexicoder LSD** (how heated). Replaces the hand-regex `GEN_PRO_RX`/`GEN_ANTI_RX` + the graded `TONE_LEXICON`/`score_graded` "degree valuation". Stance and tone stay as separate audit columns AND aggregate into ONE downstream press measurable for the Moneyball: **`press_value = stance_sign(-1/0/+1) x LSD intensity(|net|/words)`**. Plan: zero-shot DEBATE first (few-shot only if it underperforms); keep the legacy regex score as a parallel comparison column through the transition; validate DEBATE stance vs a hand-coded set (accuracy/F1/Cohen's kappa). Recency decay stays, rewired to the new aggregate column.

### ENVIRONMENT CONSTRAINTS (both discovered the hard way)
- **quanteda is UNUSABLE on this R 4.6.0** - it imports `RcppParallel`, which **segfaults on load** (verified: base R/stringi/Rcpp/Matrix/fastmatch all load fine; RcppParallel CRASHES; no Rtools installed to source-compile a fix). So LSD does NOT use quanteda. Instead the LSD2015 dictionary was downloaded from Soroka's authoritative source (https://www.snsoroka.com/s/LSDaug2015.zip), the `.lc3` files parsed by `parse_lsd.R` -> `lsd_dict.rds` (positive 1709, negative 2858, neg_positive 1721, neg_negative 2860 - IDENTICAL counts to quanteda's `data_dictionary_LSD2015`). `stage5_lsd.R` implements `lsd_tone()` on **stringi** (stable) via 4 prebuilt alternation regexes, negation phrases matched+stripped first for precedence. Validated (pro +4 / negated 0 / neutral 0); **9.6 ms/doc**.
- **NO CUDA GPU** - the machine has **Intel integrated graphics only** (the user's "my GPU can handle it" referred to the collector's browser shards, NOT CUDA). DEBATE runs on **CPU**: Python 3.12 venv at `.venv_debate` (installed via winget Python.Python.3.12), CPU torch 2.12 + transformers 5.12. `stage5_debate.py` is the sidecar (R writes input CSV -> python -> stance CSV). Model `mlburnham/Political_DEBATE_base_v1.0` (base, CPU-friendly). Validated: support 1.00 / oppose 0.99 / neutral 1.00; **~0.3 s/doc on CPU** (~1h for 10k - tractable). `--model` can swap to the large model.

### FIRST-RUN FINDINGS (2026-06-21, smoke test on 15 + corpus stats) - two real issues
1. **Only 41% of the 3637 scored releases have body TEXT** (1504/3637). The rest are `billstatus:` bill-sponsorship entries (NO text - the cosponsor-rescued rows) + americascreditunions.org / committee / news items whose bodies are not in the per-member `pr_checkpoints/fulltext/<bg>.rds` cache. DEBATE+LSD need text. **Implication: HYBRID** - DEBATE+LSD for text-bearing releases; KEEP the existing bill-signal (BILLS table) for `billstatus:` entries (a bill sponsorship's stance comes from the bill, not text). (Implemented the same day, see below.)
2. **DEBATE returns mostly NEUTRAL on the corpus - and is largely CORRECT.** The releases the regex flags are heavily "tracked bill only" / "anti-big-bank" / tangential (Social Security, floods, homeownership): they mention a tracked bill or bash banks but take NO explicit CU stance, so DEBATE (reading text) says neutral while the regex scored +1. Real regex-vs-DEBATE disagreement, not a bug (DEBATE detects stance fine on clear text). Confirms the labels may need tuning + that hand-labeled ground truth (the 45-release template) is NEEDED to know if neutrals are right.

### VALIDATION DONE (2026-06-21; 45 releases labelled by Claude as a human stand-in, coded by stance toward CU INTERESTS)
**DEBATE beats the regex ~2:1 by Cohen's kappa - DEBATE acc 0.667 / macroF1 0.578 / kappa 0.339 vs regex acc 0.444 / F1 0.413 / kappa 0.167.** DEBATE is precise on neutral (F1 .77) + support (.62) and does NOT over-flag; its weakness is OPPOSE (F1 .35) - it misses IMPLICIT policy-anti stances (e.g. Credit Card Competition Act / interchange: reads "fighting Wall Street banks", cannot infer CUs oppose it -> calls it neutral). The regex over-flags badly (21/32 of the neutrals it wrongly scored +/-1 from tangential bill-name/tone matches) but catches the policy-anti bills via the BILLS table (oppose F1 .67) -> empirical case for the HYBRID. Caveat: labels are Claude's reads (kappa 0.34 = "fair"); a human pass would firm it up; there is a real interpretation fork - EXPLICIT CU sentiment (what DEBATE measures) vs POLICY-INTEREST stance (what the Moneyball needs) - which the hybrid bridges.

### HYBRID BUILT + smoke-tested (in `run_stage5.R`, 2026-06-21)
Text-bearing releases (body >= 300 chars) -> DEBATE stance x LSD intensity; text-less `billstatus:` sponsorship entries -> the bill's known CU-stance = sign(legacy score) x `CU_S5_BILL_WEIGHT`(0.03). Adds column `stance_src`(bill|debate). Only 41% of the 3637 have body text; the 59% billstatus get the bill signal. **Full `run_stage5.R` pass on all 3637 launched (background, ~18min).**
