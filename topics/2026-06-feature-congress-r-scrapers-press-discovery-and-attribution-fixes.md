## Press scraper: fallback chain, third-party sources and coverage work

### DISCOVERY-truncation fixes: sitemap completion (2026-06-20)
User supplied 3 missing CU URLs (a Tim Scott section 1071 press release + 2 America's Credit Unions articles); ALL were missing at the DISCOVERY stage (not in index -> never fetched/scored), not fetch/attribution. Root cause: **paginated member listings dead-end at page 1.** Tim Scott (S001184, **Senate Banking CHAIR**) had only **20** releases indexed (scheme=pagenum, n_items_p1=20); his listing is an AJAX/"load more" page that ignores `?page=`/`PageNum_rs=`, so `crawl_member_index`'s page loop got page 1 then dead-ended (3 misses -> break). The existing archive-fallback (`discover_member`, ~line 1292) only fires for scheme `none`/`NA`, NOT for a detected-but-truncated pagination scheme. **Scope: 38 members truncated** (index ~ page 1, <60 releases; schemes pagenum/qpage0/qpage1/none/cdx) incl. the two most CU-relevant people - Scott (Banking) + **Brett Guthrie (House Financial Services CHAIR)** - plus Cornyn, Murkowski, Padilla, Young.
**FIX (`cu_press_release_scraper.R`):** (1) in `crawl_member_index`, after the page loop, if a paginated/none scheme yielded `<= SITEMAP_COMPLETE_MAXPAGES`(2) pages, union the site's XML sitemap via existing `sitemap_items(org)` (already filters to press paths via `PRESS_PATH_RX`, which matches senate/house `/media-center/press-releases/`); senate.gov/house.gov Drupal expose `<domain>/sitemap.xml` -> `press_releases-sitemap*.xml`. Deep crawls that paginate fine (many pages) are skipped -> no cost. (2) `retry_failed_checkpoints` now also clears the INDEX checkpoint (keeps discovery) of paginated members where `crawl_rows <= n_items_p1+2` so they re-crawl with completion (self-healing each run). VERIFIED: **Scott 20 -> 2,999 releases, the section 1071 URL now present.** One-time expansion of all 38: `refresh_truncated_indexes.R` (kept).
- **ACU news = SAME failure mode (2026-06-20):** `crawl_news_source` fetched the `/news-media` landing page (JS shell exposing ~4 FEATURED links statically), `nrow>=3` passed, so the sitemap (full archive) was never consulted -> only **4** ACU articles cached, new ones (the user's 2) missed. FIX: `crawl_news_source` now ALWAYS unions `sitemap_items` (newest-first via a new `lastmod` column on `sitemap_items`, sorted desc so the cap keeps recent), and `NEWS_MAX_ITEMS` raised 400 -> **3000** (env `CU_PR_NEWS_MAX`; a CU association source is ~100% on-topic unlike ~1% member press, and the fetch is checkpointed = one-time). VERIFIED: ACU crawl **4 -> 2,351 items, both user URLs found** (acu3 @ pos 7, acu1 @ 1450 - needs the >400 cap).
- Note: the member-discovery fix ALSO independently captures the signal behind all 3 URLs (Scott's own 2,999 releases cover his section 1071/regulatory stance; the housing bill via the cosponsor stage), so ACU is redundant secondary coverage. Sequencing: pipeline step-1 collector reads the index step-2 scraper rebuilds - so after expanding indexes, the NEXT `Rscript run_cu_pipeline.R` fetches+scores the recovered archives (the pre-expansion via `refresh_truncated_indexes.R` collapses it to one run).
- **Index junk guard + scoring diagnostic (2026-06-20):** added `is_junk_url()` (next to `PRESS_PATH_RX`) - rejects listing/section-root pages, RSS/taxonomy, pagination, assets, tel:/mailto:, and footer phone-number slugs from the index; CAPTURE-SAFE (keeps numeric-permalink articles like /release/16653/ and date-fragment slugs like /.../9/11 and IQ-CMS ?ID=/?ContentRecord_id= articles). Validated 10/10 junk caught, 6/6 real kept. Mirrors `is_junk_body()` (the body-cache WAF/nav guard added the same day).
- Diagnostic review of the 4.3k-line codebase found+fixed: (1) **BUG in `stage_score`** - `full |> left_join(bind_rows(res), by="url")` was many-to-many because `res` is row-aligned with `full` and the additive layers (manual-CSV + crawled news, etc.) carry the same article twice -> DOUBLE-COUNTED that release in member rollups (+ the "many-to-many" warning). Fix: `full <- full[!duplicated(full$url),]` up front -> 1:1 join. (2) **STREAMLINING** - `score_release` scanned PRO_CU_PHRASES/ANTI_CU_PHRASES twice (a misleading "hoisted, no double scan" comment); now counts hits in the single phrase loop. (3) **OPTIMIZATION** - `score_bill_signals` looped all 53 bills x ~2 grepl on EVERY release (~28M regex passes); added `ALL_BILLS_NAME_RX`/`ALL_BILLS_NUM_RX` single-pass pre-filter so the ~99% of releases mentioning no tracked bill skip the loop (behavior-identical: union cannot match -> no member can). Noted-not-fixed (lower value): `weighted_tone` triple loop (CU-relevant subset only), `fetch_member_fulltext` `flush_ck` O(n squared) re-bind (JS path, budget-bounded). ### Recency decay (added 2026-06-20; user request "newer releases given more prominence")
Member/category ROLLUPS are decay-weighted - each release weighted `0.5^(age_years / DECAY_HALFLIFE_YEARS)` (newest=1, one half-life=0.5). Constant `DECAY_HALFLIFE_YEARS` (env `CU_PR_DECAY_HALFLIFE`, default 2y; 0/Inf/NA disables -> all weights 1) + helpers `recency_weight(dates)` and `wmean(x,w)` (safe weighted mean, falls back to plain mean on zero/absent weights). Per-release scores in "Scored Releases" stay RAW/auditable; only aggregates weighted. Threaded through: `scored$recency_weight` (set in `stage_score`), carried by `explode_categories` into `cat_long`, then applied in: summary `net_score=sum(score*w)` + `member_lean=wmean(score_graded,w)` (drives the member stance label + ranking); `cat_detail` net; `mk_wide` net/graded (xtabs on precomputed `net_rw`/`graded_rw`); `build_net_by_category` per-category + Cumulative Net (NET columns now NUMERIC/doubles, were integer - counts/(n)/Total stay integer); `detect_coalitions` mat + lean_full via wmean. Every weighting point guards `if(!"recency_weight"%in%names(...)) <-1` so offline fixtures (undated) = weight 1 = unchanged. `test_cu_scoring_offline.R` updated (5 net-sheet `want` int -> numeric) + 7 new decay/wmean checks = **179/179 PASS**. Verified in a live run: year filter (index 290,778 -> 250,420 @2022 floor) and sitemap truncation fixes (Cantwell 6,106, Lankford 3,649, Thune 2,983) both confirmed working.

**RE-RESTORED the year filter + recency decay (2026-06-21):** the user reversed course ("revert to having the guard-dog and year filter") - the 2022 floor AND the decay weighting are BACK IN. `DATE_FLOOR <- as.Date("2022-01-01")`; all decay code re-applied (`DECAY_HALFLIFE_YEARS` env `CU_PR_DECAY_HALFLIFE` default 2y, `recency_weight`, `wmean`, the weighted summary/cat_detail/mk_wide/build_net_by_category/detect_coalitions rollups, net columns numeric again); offline suite back to **179/179**. **"Guard-dog" (user's term) = the collector's PER-SHARD STALL WATCHDOG** in `cu_text_collector.R` (the orchestrator loop: `kill_shard` tree-kills a wedged worker + its Chrome children via `taskkill /F /T`, `spawn_shard` respawns it resuming-from-cache; keys on the `.hb` heartbeat FILE mtime; knobs `CU_TC_WATCHDOG_MIN=10`min, `CU_TC_MAX_RESPAWN=2`). (NOT the `is_junk_body`/`is_junk_url` guards, which the assistant mislabeled as "guard-dog" first - those are also still active but are a different thing.) ### News attribution common-word-surname bug + honorific guard (2026-06-21)
- Comparing the net-by-category output exposed that third-party/trade-press articles (esp. the ~2,300-article America's Credit Unions newsroom) were MASS-MISATTRIBUTED to members whose surname is a UNIQUE-but-COMMON-WORD: Jim **Banks**(319), Dale **Strong**(281), Wm **Timmons**(258), Michael **Simpson**(210), French **Hill**(201), Wesley **Hunt**(141) - all > the real HFSC chair. Cause: `members_in_text` (the news free-text detector) attributed a BARE surname whenever it was unique in Congress (`idx$uniq`), so "banks"(institutions)/"strong support"/"Capitol Hill"/"the hunt" each vacuumed up every article containing the word; their "releases" were ACU titles ("Nussle...", "FedNow...", "Q4 GDP report").
- FIX: bare-surname attribution now requires a congressional honorific adjacency - `HONORIFIC_RX` = `(?:rep|sen|representative|senator|congressman|congresswoman|congressmember|chair(man|woman)?|ranking member)\.?` immediately before the surname; FULL name (first+surname) still attributes unconditionally; non-unique surnames still need the first name. Verified 13/13 cases ("Capitol Hill"/"community banks" -> none; "Rep. Hill"/"Sen. Banks"/"Tim Scott" -> attribute; ambiguous "Sen. Scott" -> none) + offline 179/179. NOTE: this only touches the news/thirdparty path (`thirdparty_rows` -> `members_in_text`); committee uses `attribute_statement_to_member`/`match_one_member` (controlled headlines, left as-is). Re-scored after: total 5594 -> 4059; Strong 281 -> 3, Simpson 210 -> 3, Hunt 141 -> 2, Hill 201 -> 50 (realistic HFSC chair), controls Andy Barr 52 -> 48 / Schiff 8 -> 8 unchanged.
- TWO RESIDUALS the honorific pass exposed: (1) **Jim Banks 319 -> 109** - the FULL-NAME branch matched first+surname as separate co-present words, and ACU's CEO is **Jim Nussle** (in every article) + "banks"(institutions) everywhere -> false "jim"+"banks". FIX: full name must be ADJACENT `\bfirst\s+surname\b`, not co-present (verified: "Jim Nussle praised community banks" -> none; "Jim Banks introduced" -> Banks). (2) **William Timmons 258 -> 257 (NOT fixed by attribution)** - 231/257 are his OWN site timmons.house.gov, a mis-scraped IQ-CMS/Dojo JS-shell: ALL titles extract as "Join My Email List" (nav CTA), dates fail (a 2019 "opens district offices" page leaked past the 2022 floor as undated), crawler captured garbage Dojo URLs (.../dijit/dijit/dojo/dojo/dom-construct), bodies over-tag "Examination & Supervision" via his SMART Act ("**Supervisory** Modifications for Appropriate Risk-based Testing"). ### Parallel-scoring `full`-capture bug + `CU_TC_ONLY` targeting + collector self-locate (2026-06-21)
The Stage-5 parallelization was SILENTLY FALLING BACK TO SERIAL at scale - the nested `score_row` defined inside `stage_score` closed over the function's frame, which holds the ~2 GB `full` frame, so `future` tried to export 2 GB/worker and tripped `future.globals.maxSize` (500 MB); the tryCatch swallowed it -> serial. (The earlier small-fixture test never tripped it because `full` was tiny.) FIX: hoisted the scorer to TOP-LEVEL globals `.cu_score_row` + `.cu_score_chunk` (defined just before `stage_score`), `future_lapply(parts, .cu_score_chunk, ...)`. Verified via `globals::globalsOf(.cu_score_chunk, recursive=TRUE)`: 113 globals, **`full` NOT included**, total export 2.31 MB (largest are base `data.frame`/`regmatches`) -> no fallback at the 500 MB default. LESSON: never let a future-exported closure be defined inside a frame that holds a big object; define worker fns at top level.
Added collector knob **`CU_TC_ONLY`** (comma-sep bioguide allowlist; pair with `CU_TC_CAP=0`) for targeted member re-fetch, e.g. `CU_TC_ONLY="B001303,..." CU_TC_CAP=0 CU_TC_PROCS=8 Rscript cu_text_collector.R`. `cu_text_collector.R` now ALSO self-locates (same `--file=` setwd as the pipeline). Context: shard 10 of the 12-worker run = 23 bot-blocked members (Blunt Rochester B001303 560u, Owens, Marshall, Massie...) reconstructable by replaying the planner (greedy balance is deterministic; the live plan is auto-unlinked); the assistant finalized it early (writeLines .done + tree-kill) thinking it was zero-yield, but the log showed chromote WAS productive (~40%), so re-fetching all 23 (`CU_TC_ONLY`, CAP=0, 3278 urls) to close the gap, then re-score.

### Collector per-shard stall WATCHDOG + pipeline self-locate (2026-06-20)
A 12-worker collector run wedged: 6/12 shards (chromote/403 pass) froze within a ~3-min window ~18m in (transient network/CDP-socket hang), all heartbeats stale; the orchestrator's only guard was an AGGREGATE `IDLE_MIN=20` that abandons everything + leaves zombie Rscript+headless-Chrome. Fix: each WORKER writes `collector_shard_i.pid` at startup; the orchestrator runs a PER-SHARD watchdog in its 30s monitor loop -> if a non-done shard's `.hb` mtime is stale > `CU_TC_WATCHDOG_MIN`(10) it tree-kills it (`taskkill /F /T /PID`, which also kills that worker's child Chrome - chromote launches Chrome as a child of the worker, so other shards/the user's browser are untouched) and respawns it (`spawn_shard`); respawn re-derives todo = plan-shard minus cached_good, so it RESUMES. Bounded by `CU_TC_MAX_RESPAWN`(2); after that the shard is marked `.done` (writeLines "0") and its gap -> residual. Liveness made responsive: `write_hb()` now also fires every 200 bodies mid-main-pass and every 10 urls in chromote (was only per-chunk/per-50). Verified: collector parses; `taskkill /F /T /PID` kills a live process (alive before=T, after=F).
- SAFE-KILL recipe for a wedged collector: `Get-Process Rscript | Stop-Process -Force` + tree-kill only chrome.exe whose CommandLine has `--headless` and NOT `--type=` (the headless ROOT; /T cascades to children) - never blanket-kill chrome.exe.
- CAVEAT: force-killing a worker loses its UN-flushed in-memory bodies (main pass flushes only at shard-end via `s0+CHUNK>n`, `FLUSH_EVERY=8000` too coarse to trigger mid-shard; chromote flushes every 50) -> resume re-fetches them (cheap curl). Possible follow-up: flush main pass per-chunk.
- `run_cu_pipeline.R` now self-locates (resolves its own `--file=`/`ofile` dir and setwd there) so "missing cu_text_collector.R (run from project dir)" cannot recur regardless of launch cwd.

### Stage-5 scoring parallelized + REVIEW Act false-match fixed (2026-06-20)
`stage_score` was SERIAL (`lapply` over ~250k releases); now parallelized across the SAME `CU_PR_WORKERS` (=`FUTURE_WORKERS`) pool Stage 4 uses - split `full` into `FUTURE_WORKERS*3` contiguous chunks passed AS DATA (so the 250k frame is not exported whole to each worker), `future_lapply` each, `do.call(c,...)` to concat in order; gated on `FUTURE_WORKERS>1 && n>4000`; wrapped in tryCatch -> serial fallback. VERIFIED parallel == serial bit-for-bit on a 5,200-row synthetic (4,644 == 4,644, scores/bills/order identical) + offline 179/179. So `CU_PR_WORKERS=6` now drives discovery + index + Stage-4 PARALLEL fetch + Stage-5 scoring (6 workers each). `FUTURE_WORKERS` comment updated. IMPORTANT: the Stage-4 JS/chromote phase (42 seq members) stays SEQUENTIAL by design (Chrome unsafe in future workers) -> for fast PARALLEL fetch incl. chromote use `cu_text_collector.R` (`CU_TC_PROCS`). Best full run with 6 workers everywhere: `CU_TC_PROCS=6 CU_PR_WORKERS=6 Rscript run_cu_pipeline.R`. (The 2026-06-21 capture bug above later showed this parallel path had been silently serial at scale.)
