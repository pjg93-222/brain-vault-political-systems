## Phase 1 - legislative-success edge weights (2026-06-25)

- Injection point: Stage 3 of `congress_member_scraper.R` (lines ~1882-1911), a DIRECTED sponsor-to-cosponsor graph keyed by bioguide; the old `Weight = Σ(1.0·original + 0.5·regular)` had no success/size/time weighting.
- `make_centrality_xlsx.R` reads the `Edges` sheet, igraph centrality, `InfluenceScore` = 0.60 WeightedOutDegree + 0.25 Betweenness + 0.15 Eigenvector, min-max to 0-100.
- Enhanced tie weight = `role × success × DecayWeight ÷ sizenorm(CosponsorCount)`.
- Success is effectively binary and chamber-aware: floor-passage of origin chamber vs stuck at introduced/committee. Bill chamber from Title prefix (H.R. = House, S. = Senate).
- `DecayWeight` already in data (0.8^age per congress). `sizenorm` options: off / 1/log2(1+C) / 1/√C / 1/C (Newman); the big "resolution" knob that de-noises blockbuster messaging bills out of WeightedOutDegree.
- Multipliers and thresholds are the user's to set; see `feedback_consult_multipliers_thresholds`.
- Deployed (x3, full network): enhanced Stage 3 (`role × success(x3 if passed-own-chamber) × DecayWeight ÷ √C`) gives `congress_cosponsor_network_20260625_184604.xlsx` (2390 edges), centrality, wired into the Blended Model `Centrality` sheet via Excel COM (0 errors, $2M, 494/533 coverage). Ranking effect: Hagerty #7 to #3, Tim Scott into the top 10 (Senate Banking bill-passers rewarded), HFSC core held. Scraper backed up to `congress_member_scraper.BACKUP-20260625.R`; model to `...PRE-CENTRALITY-20260625.xlsx`. NEXT then: stress-test this base, then Phase 2.
- **Dial update 2026-06-25:** `SUCCESS_MULT` set to **3.0** (was 5.0; x5 made the offline InfluenceScore too top-heavy: 4 members >50, 77 zeros). Retunable at top of Stage 3.
- **Base reproducibility gap RESOLVED (it was an artifact):** a standalone offline rebuild reproduced only ~81% of the 2390-edge network, but that was my script's archive-join mismatch. Running the scraper's own Stage 3 offline ("0 to fetch (393 cached)") rebuilds the FULL 2390-edge / 636-node network with the enhanced weighting; all rosters were already in `congress_cosponsor_checkpoint.rds`. ## Vote edges (DONE 2026-06-25; user chose method, delegated weighting)

- User rejected DW-NOMINATE; research (Aref & Neal) points to **Neal's signed backbone**. Built via R `backbone` pkg v3.0.4 `sdsm(B, alpha=.05, signed=TRUE, mtc="BH")` on bipartite **member x (vote,side)** so the projection = agreements (yea-yea + nay-nay), null preserves member activity + each vote's margin. `_vote_backbone.R`.
- **KEY FINDING: raw signed backbone is ~95% just PARTY** (pos 93% same-party, neg 99% cross-party), useless as-is.
- **Option C (party-controlled null, `_vote_backbone_C.py`):** expected agreement from each pair's PARTIES' per-vote propensities, sign by deviation, BH, **>=20 shared-votes floor** (kills House-to-Senate switcher artifact: Gallego 72 to 11). Sparser (33%) but **negatives still conflate maverickness** (Massie/Gosar/Roy right-flank defectors sit next to moderates; same members top BOTH +cross-party and -same-party). So **dropped the negative side**; kept **cross-party POSITIVE only** = clean bipartisan-CU-affinity signal (Fitzpatrick, Golden, Cuellar, Gluesenkamp Perez, Mace).
- **INTEGRATION:** `Vote Affinity` = percentile rank of summed cross-party-positive z; added as col I to the 3 flip tables in **Signed Coalitions** sheet, plus col J `Priority = 0.70·z(Index) + 0.30·z(VoteAff)` (cosponsorship stays primary; votes a 30% corroborating booster); tables re-ranked. Votes surface cross-pressured persuadables cosponsorship missed (Neutrals: Slotkin +31, Moulton +29, Joyce, Stanton, Turner; Skeptics: Van Orden, Cleaver, Carson, Heinrich climb). 21 freshmen (<20 votes) get affinity 0 = rank on cosponsorship only. ## Phase 3 - influence maximization / adaptive allocation (BUILT 2026-06-26, `fec/im_allocate2.py`)

- Two modes per the research. **FLIP = competitive Linear Threshold (Borodin)**: `P_flip = A/(A+B)`, `A = √(cu+alloc)` + proximity-to-allies, **`B` = congestion(industry$) + proximity-to-opponents** (the user-specified competitive factors); greedy (1-1/e, last-mover). **COALITION = competitive Independent Cascade (Bharathi-Kempe)**: MC cascade, A-seeds = pro, B-seeds = anti, full-budget allocation ∝ marginal A-spread (capped $50k). $-to-weight via Kalla-Broockman.
- **Per-sub-category variants:** flip run per legislative topic (18), strategic value = member's activity on THAT topic (`per_topic_flip.py` to `per_topic_alloc.json`).
- Wired to the model as **`IM Allocation` sheet: mode switch in cell B1 (FLIP/COALITION), Active $ formula follows, plus 18 topic columns** (`write_im_sheet.py`, backup PRE-IM-20260626). Dials: `WM`/`WP` money-vs-proximity (0.6/0.4), `PERS` by stance, `CAP` $50k.
- **FP BILLS CLEANED FROM LEGISLATIVE PILLAR (DONE 2026-06-26, surgical, NOT a refresh)**: per user, with centrality out of the rank, cleaned the 36 FPs. Method = scale each FP-cosponsor's frozen Normalized down by their **FP share of that topic** (`cleaned=frozen×(1−fp_share)`, share from interaction-sheet decay); curated values preserved for non-FP-cosponsors, no rescale/un-freeze. Result: 0 errors / $2M / 133, only 23 members moved >=15 ranks (Pallone/Kaptur/Dingell, George-Floyd/broadband cosponsors), **Barr/Scott/Durbin unchanged** (vs the refresh's 308-stance-change disaster). `fec/compute_fp_clean.py` + `write_fp_clean.py`, backup PRE-FPCLEAN-20260626. **22-check audit passed (`fec/audit.py`).** Centrality stays out of rank (committee-only influence); the failed legislative refresh stays reverted.
- **Phase 3 design (grounded before build):** goal-conditioned influence-max, objective configurable per **legislative domain/category** (the Primary Layer's 17 grouped topics: "kill an interchange bill", "pass a FOM bill"). TWO MODES specified by the user:
  - **Coalition building to Independent Cascade Model** (Bharathi/Kempe/Salek "Competitive Influence Maximization" = competitive IC; Trivedi/Singh Procedia 2020 = efficient IC via centrality heuristics, so our InfluenceScore is the seeding heuristic). Submodular, so greedy (1-1/e). Spread a position to build a supporting coalition.
  - **Vote / persuadable flipping to Linear Threshold Model** (Borodin/Filmus/Oren "Threshold Models for Competitive Influence" = weight-proportional competitive LT). Node v flips when Σ active-neighbor weights >= θ_v; adopts OUR side with prob = (our-side weight)/(total active weight), the tug-of-war with the opposing party. NON-submodular except their "OR model", so use OR-model or simulation-based greedy.
  - Must be **targeted, adaptable, and COMPETITIVE**: model the relation between a member and the OPPOSING party (opposing-party members carry the competitor color/weight; the Phase 2 signed network supplies sides; persuadables = low-threshold boundary members). Premise grounded by **Kalla & Broockman "Campaign Contributions Facilitate Access"** (RCT: donor status gives 3-4x more access to senior policymakers), so $ allocation BUYS activation probability / threshold reduction, not just seed picks. (Papers in user's Downloads: viral-competitive = Bharathi/Kempe, doc_1 = Borodin/Filmus/Oren, `1-s2.0-S1877050920315416` = Trivedi/Singh, Hertel-Fernandez-2 = actually Kalla/Broockman.)
  - **Adaptive backbone = Golovin & Krause "Adaptive Submodularity" (JAIR 2011, in Downloads).** Fund a member, observe persuaded/who-they-bring, adaptively pick next. Adaptive-greedy = (1-1/e) of optimal policy when the objective is adaptive-monotone + adaptive-submodular; alpha-approx greedy gives (1-1/e^{1/α}); the cost-sensitive version maps the $ budget to per-member costs c(e). Adaptive IM (coalition/ICM mode) IS adaptive submodular, so a clean guarantee; competitive-LT flip mode is generally NOT, so OR-model/heuristic path.
