## congress.gov member scraper (`congress_member_scraper.R`)

### Purpose and outputs
Main project in the directory: a multi-layer R web scraper for congress.gov. Uses chromote (to bypass 403), user-agent rotation, randomized back-off, and `future`/`future.apply` parallelism. The original scraped a single search across many page numbers; it was re-oriented so the switch variable is the MEMBER OF CONGRESS (the `original-cosponsor` value in an advanced-search query). Purpose (the Why): measuring legislative activity (insurance/data-privacy/financial-services bills) per individual member across congresses 119/118/117/116.

Two original outputs: `Bills_Individual` (one row per bill) and `Members_Statistics` (one row per member, including the summed Bill Count facet `#innerbox_congress .count`). New per-bill nodes: Title `.result-title`, Sponsor `.result-title + .result-item a:nth-child(2)`, Committee `.result-item:nth-child(5)`, Last Action, Cosponsor count.

### Result-row markup (confirmed from dumped HTML, 2026-06-02)
- Each bill is `li.expanded` (a hidden `li.compact` duplicate follows - scrape only `li.expanded`). Inside: `.result-heading a` (bill no.), `.result-title`, then `.result-item` spans for Sponsor / Committees / Latest Action, plus `.result-item.result-tracker`.
- **Cosponsor count** = TEXT of the cosponsors link: `<strong>Cosponsors:</strong> (<a href=".../cosponsors...">42</a>)`. Parse via `html_nodes(bill,"a[href*='cosponsors']")` -> integer. The old `gsub("\\D","",cosLine)` glued the Introduced date onto the count -> values in the thousands (fixed). Fallback regex `Cosponsors:\\s*\\(\\s*[0-9]+`; default 0.
- **Last Action -> short status:** congress.gov tracker carries it as `<p class="hide_fromsighted">This bill has the status X</p>` where X is exactly the wanted label. Observed values across the full roster: Introduced, Passed House, Became Law, Passed Senate, Resolving Differences, Agreed to in House. Extract with `sub(".*has the status","",...)`; fallback `classify_last_action()` keyword-maps the raw "Latest Action:" text.
- **AvgCosponsors NaN -> 0:** `mean()` of an all-NA group is NaN; `member_agg` now uses `ifelse(all(is.na(CosponsorCount)),0,round(mean(...,na.rm=TRUE),2))`, and the Members `left_join` coalesces NA/NaN AvgCosponsors and NA TotalCosponsors to 0.

### Whole-roster scale and the cookie-replay fast path (2026-06-02)
- `FETCH_MODE` (`"http"` default / `"browser"`): http harvests Cloudflare cookies + UA once from the real browser (`harvest_cf_session()` -> `Network$getAllCookies`, saved to `cf_session.rds`), then fetches every page with parallel `httr::GET` (no render) via `plan(multisession, workers=HTTP_WORKERS=6)`. `fetch_html_http()` returns parsed HTML, `"CHALLENGED"`, or NULL. `fetch_page()` dispatches http -> browser.
- The harvested session is threaded as an explicit `cf=` argument through `scrape_member_overview`/`scrape_detail_page`/`fetch_page`/`fetch_html_http` so it serializes to future workers (default-arg globals are not reliably exported).
- Driver: harvest once -> parallel http in rounds; members returning status `"challenged"` get the cookie re-harvested and retried; any still challenged fall back to the browser sequentially in the MAIN process (workers cannot reach the browser).
- Known risk (as written 2026-06-02): `cf_clearance` may be TLS-fingerprint-bound, so httr replay can be re-challenged; `validate_http()` (run once) tells you if the fast path works; if not, set `FETCH_MODE <- "browser"`. UNVERIFIED at the time - then VERIFIED by the first full 119th roster run (see Rules: no Cloudflare challenges, 536 members, 1773 bill rows).
- Roster: `get_roster_119()` pulls current House+Senate (536 names) from `https://unitedstates.github.io/congress-legislators/legislators-current.csv` (NOT theunitedstates.io - that redirects to HTML; NOT raw.githubusercontent - 404). Gate with `USE_FULL_ROSTER <- TRUE`. Added `library(httr)`.

### Root cause of zero nodes = Cloudflare, bypass applied 2026-06-02
Diagnostics showed every page returned `title = "Just a moment..."` (Cloudflare interstitial) - NOT a URL or selector bug. URL construction is proven byte-identical (6922 chars; see Rules). The browser layer was rewritten:
- Replaced the mismatched multi-engine `user_agents` rotation (a bot signal) + `plan(multisession, workers=4)` with `BROWSER_MODE` (`"remote"` default / `"headless"`), a single consistent `CHROME_UA` (Chrome 148), and `plan(sequential)`.
- New functions: `launch_scrape_chrome()` (system2-launches real headful Chrome with `--remote-debugging-port=9222 --user-data-dir=%USERPROFILE%\chrome_scrape_profile`), `init_browser()` (attaches chromote default object via `Chromote$new(ChromeRemote$new(...))`), `apply_stealth(session)` (masks webdriver/chrome/languages/plugins; UA override only in headless mode), `wait_past_cloudflare(session)` (polls title/challenge DOM until cleared).
- `fetch_rendered_html` and `scrape_detail_page` now call `apply_stealth`; `fetch_rendered_html` waits past Cloudflare before reading DOM. `debug_member` and both `RUN_FULL` driver blocks call `init_browser()`. Removed the `mem_used()` line (pryr not loaded, was crashing). File parse-checked OK under Rscript.
- **Workflow (remote mode):** `launch_scrape_chrome()` (opens real Chrome - solve any captcha by hand ONCE, cookie persists in the profile), `validate_http()` to confirm the cookie-replay path, then source with `RUN_FULL <- TRUE`.

### Roster naming (fixed 2026-06-10; user: "James McGovern" miscalled)

### 5-step fallback chain for MANUAL_PRESS_URLS members (added 2026-06-12)

### Text-collection anti-stall hardening (2026-06-18)
Stage 4 full-text used to "silently stall": the sequential JS-member block (`res_js <- lapply(seq_bgs,...)` in `stage_fulltext`, main process, workers idle) emitted NO progress and `fetch_html_js` ran synchronous chromote CDP calls (`Page$navigate`/`Runtime$evaluate`) with NO wall-clock cap, so one wedged headless tab blocked forever; `FULLTEXT_MODE="all"` made every release walk static -> chromote -> Wayback (60-90s) serially, and the per-member checkpoint saved only at the END (a mid-member stall lost all its work). 1. 3. Incremental checkpoint every `CKPT_EVERY<-25` urls (`flush_ck`) so a stop/stall never discards completed fetches.
4. Per-member heartbeat in the seq JS block (`JS [k/n] bg: N urls -> M bodies (Ns)` + `flush.console`) - kills the "silent".
NOT done (optional next lever): parallelizing JS members across a chromote-session pool (deliberately kept sequential - chromote-in-future-workers is unsafe). ### Fast analyzer `cu_text_collector.R` (2026-06-18)
- The `future`/synchronous Stage-4 fetch in the main scraper never finished (>10h, partial coverage) - root cause MEASURED: not network but **parse**. `read_html`+`extract_release` = **~62ms/page = ~16 pages/s on ONE core**; a single process is parse-bound (~4.7h for 273k). Network (libcurl multi, HTTP/2 multiplexed) is ~12.7 url/s per host but many hosts run in parallel, so it is not the cap.
- Solution = a separate drop-in collector that **parallelizes parse across cores by sharding members across N worker PROCESSES** (each owns distinct hosts -> per-host politeness automatic), each worker running an **async curl multi pool** (`TOTAL_CON` 24, `HOST_CON` 6, multiplex) so fetch overlaps parse. It REUSES the scraper's `extract_release` (sources it with `CU_PR_NO_AUTORUN=1`) and writes the SAME `pr_checkpoints/fulltext/<bg>.rds` (url,title_detail,date_detail,body) the scorer reads - so scoring/Stage5+ unchanged.
- Default role = orchestrator: `Rscript cu_text_collector.R` auto-launches `CU_TC_PROCS` (default 6) worker subprocesses (`Rscript cu_text_collector.R <i> <n>`, logs to `collector_shard_i.log`), prints ONE aggregate heartbeat (bodies cached / url-s / ETA / shards-done by polling fulltext + logs), then writes `collector_residual.csv` (members still missing bodies -> feed to the main scraper's chromote/Wayback lane). Resumable (skips urls with body+date), incrementally checkpointed (flush every `CU_TC_FLUSH=8000`), no chromote in hot path -> cannot hang.
- **Measured ceilings: 6 cores ~ 47min, 8 ~ 36min** (vs >10h). Knobs: `CU_TC_PROCS`/`TOTAL_CON`/`HOST_CON`/`CHUNK`(1500)/`FLUSH`/`LIMIT`(dry-run)/`CU_CKPT_DIR`(alt store)/`CU_TC_SHARD`("i/n"). Integration-tested end-to-end on a temp store (orchestrator + 2 workers + limit). Validated parse fix: top-level multiline `if/else` in an R assignment is a parse error - keep `x<-if(c)a else b` on one line or use a separate `if`.
- Workflow: (1) `Rscript cu_text_collector.R` (~47min, fills ~all bodies), (2) check `collector_residual.csv`, (3) `Rscript cu_press_release_scraper.R` (residual JS/Wayback + score) or `CU_PR_OFFLINE=1 ...` to score cache only. RAM: ~450MB/worker -> 6 procs ~3GB (safe with ~6.9GB free); set `CU_TC_PROCS=8` if RAM freed.
- **Optimization round (2026-06-18):** parse re-measured at ~30ms/page on typical pages (62ms was the one giant member's heavier pages) -> real run ~30min @6 cores. Stripping `<script>/<style>/<svg>` before `read_html` measured ZERO speedup (cost is core libxml2 parse, not inline JS) - ruled out, do not retry it. Six wins applied and integration-tested: (1) **shards balanced by URL count** (greedy: heaviest member -> lightest shard, via orchestrator-written `collector_plan.rds`) instead of name-hash, so no shard becomes the tail; (2) **one persistent curl pool per worker** (was per-chunk) -> HTTP/2 keepalive survives across chunks (later changed, see 2026-06-19 crash fix); (3) **retry only transient** (libcurl `fail` + HTTP 5xx); 4xx and empty-200 (JS-only) are permanent `miss`, no wasted second pass - big win on Wayback/dead-URL members; (4) orchestrator builds ONE plan (single index+cache scan) and workers read their slice -> no 6x redundant full scans, lighter workers; (5) heartbeat reads cheap cumulative "ok N" from shard logs (not re-reading all fulltext rds every 30s) + **stall guard** (break if no progress 10min -> survives a crashed worker); (6) `TOTAL_CON` 24 -> 40 (Little's law: ~0.8s latency x ~40/s core needs ~32 in-flight to not starve parse). Plan auto-unlinked at end.

### Graded scale (2026-06-14, augmented from four methods papers)
The CU press scorer (Stage 5) was augmented 2026-06-14 from four methods papers into a graded, multi-dimensional, coalition-aware scorer. The legacy integer `score` (-1/0/+1, NEUTRAL_BAND=2) is preserved bit-for-bit; new fields are ADDITIVE.
- **Graded scale (Haselmayer & Jenny 2017 + Rice & Zorn 2018):** `TONE_LEXICON` data frame carries per-stem intensity weights (1 weak / 2 mid / 3 strong) mirroring GEN_PRO_RX/GEN_ANTI_RX stems. `weighted_tone()` scans CU sentences applying valence shifters; predecessor tokens are derived from the prefix string (not a separate tokenization) so leading/double spaces cannot misalign them. NEGATORS_RX drops the word if it sits in EITHER of the two preceding tokens (2-token reach catches refusal frames "refuses to support"/"failed to protect" that a 1-token window scored as praise); AMPLIFIERS_RX x1.25 (`AMPLIFY_FACTOR`) and DOWNTONERS_RX x0.75 act on the immediate token only. Specific phrases + bill stances enter at weight 3. `graded_from_signed()` adds `+ 0` to collapse IEEE -0.0 -> +0.0. `graded_from_signed(Wp-Wn)` buckets |signed| by `GRADED_CUTS=c(1,2,3.5,5.5,8)` into 0/.2/.4/.6/.8/1.0 (rounded 1 dp).
- New scored columns: `score_graded` (+1..-1 by 0.2), `score_label` (symmetric "Strongly negative" etc.), `negativity_label` (user's framing: non-negative -> "Not negative (neutral or positive)", else 5 negative levels), `polarity` (Rice & Zorn normalized (Wp-Wn)/(Wp+Wn)), `pos_weight`/`neg_weight`.
- **Strong-tier anchor cap (`GRADED_STRONG_CAP=0.6`, added in the 2026-06-14 audit):** reaching "strongly"/"very strongly" (|graded|>=0.8) now REQUIRES a concrete CU anchor - a tracked-bill stance (`any(bills$signal != 0)`) OR an explicit PRO_CU_PHRASES/ANTI_CU_PHRASES hit. Tone-only releases (generic praise/criticism, no bill, no CU phrase) are capped at +/-0.6, with a "graded capped..." note appended to `evidence`. Sign and the legacy integer `score` are NEVER changed. Motivation: audit found 86 releases >= +0.8 vs only 2 <= -0.8, with inflated tops like Cotton +1.0 from the single word "applauds" and Barr +0.8 on a community-BANK release. Post-cap live: 28 demoted to +0.6; ALL 58 remaining +0.8/+1.0 are bill- or phrase-anchored. The phrase-hit `vapply` calls are hoisted (`pro_phrase_hits`/`anti_phrase_hits`) so they feed BOTH Wp/Wn and the anchor test.
